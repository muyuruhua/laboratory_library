# Lattice-MAB 策略激进优化说明（V3）

## 优化目标

基于测试结果（执行次数 +2.15%，覆盖率效率 -2.09%），实施更激进的优化以：
1. **减少执行次数**（目标：< 88775，减少至少 4%）
2. **减少循环数**（目标：< 73，减少至少 4%）
3. **提高覆盖率效率**（目标：> 0.000191，提高至少 5%）
4. **保持覆盖率**（≥ 17）

## V3 优化措施

### 1. 进一步降低探索参数（-50%）

| 参数 | V2 值 | V3 值 | 变化 |
|------|-------|-------|------|
| `MAB_ALPHA` | 0.01 | **0.005** | -50% |
| `MAB_EPSILON` | 0.02 | **0.01** | -50% |
| `NEIGHBOR_EXPLORE_PROB` | 5% | **2%** | -60% |

**效果**：大幅减少探索，几乎完全利用已知高效策略。

### 2. 增强效率惩罚（+67%）

| 参数 | V2 值 | V3 值 | 变化 |
|------|-------|-------|------|
| `EFFICIENCY_PENALTY_FACTOR` | 0.3 | **0.5** | +67% |
| `EFFICIENCY_THRESHOLD` | 50 | **30** | -40% |
| 惩罚计算除数 | 100.0/50.0 | **50.0/30.0** | 惩罚更强 |

**效果**：更早、更强地惩罚低效策略。

### 3. 提高效率奖励权重（+50%）

| 参数 | V2 值 | V3 值 | 变化 |
|------|-------|-------|------|
| 效率奖励权重 | 20.0 | **30.0** | +50% |

**效果**：效率成为奖励计算的主导因素。

### 4. 实施直接效率筛选（新增）

#### 4.1 UCB 选择中的直接筛选
```c
// 直接跳过效率低于阈值的策略
if (mab->arms[i].pull_count > EFFICIENCY_THRESHOLD) {
    double efficiency = mab->arms[i].avg_reward / mab->arms[i].pull_count;
    if (efficiency < MIN_EFFICIENCY_RATIO) {
        continue;  // 完全跳过
    }
}
```

**效果**：低效策略完全不会被选中。

#### 4.2 Epsilon-Greedy 中的效率筛选
```c
// 探索时只从高效策略中选择
// 利用时基于效率选择，而不是平均奖励
double efficiency = avg_reward / pull_count;
if (efficiency > max_efficiency) {
    selected_arm = i;
}
```

**效果**：探索和利用都基于效率。

### 5. 更激进的 UCB 效率因子

| 效率等级 | V2 因子 | V3 因子 | 变化 |
|----------|---------|---------|------|
| 非常低效 | 0.4 | **0.2** | -50% |
| 低效 | 0.6 | **0.4** | -33% |
| 中等低效 | 0.8 | **0.6** | -25% |
| 轻微低效 | 1.0 | **0.8** | -20% |

**效果**：低效策略的 UCB 值被大幅降低。

### 6. 未探索策略 UCB 值进一步降低

```c
// V2: mab->arms[i].ucb_value = 1.0;
// V3: mab->arms[i].ucb_value = 0.5;  // 进一步降低
```

**效果**：更强烈地偏向已探索的高效策略。

## 关键改进点

### 1. 直接效率筛选
- **UCB 选择**：低效策略直接被跳过
- **Epsilon-Greedy**：探索和利用都基于效率
- **效果**：低效策略几乎不可能被选中

### 2. 更激进的惩罚
- 惩罚因子：0.3 → 0.5（+67%）
- 惩罚阈值：50 → 30（更早触发）
- 惩罚计算：除数从 100.0/50.0 降低到 50.0/30.0（惩罚更强）

### 3. 效率优先
- 效率奖励权重：20.0 → 30.0（+50%）
- Epsilon-Greedy 利用阶段：基于效率选择，而不是平均奖励
- UCB 效率因子：更激进的降低
