# AFL++ 模糊测试指标说明

## 指标分类

### ✅ **越高越好的指标**（表示更好的测试效果）

#### 1. **发现边数 (edges_found)**
- **含义**：发现的代码覆盖率（边数）
- **期望**：越高越好
- **说明**：这是最重要的指标之一，表示代码覆盖率。更高的覆盖率意味着测试了更多的代码路径，更容易发现bug
- **目标**：最大化代码覆盖率

#### 2. **崩溃数 (unique_crashes)**
- **含义**：发现的唯一崩溃数
- **期望**：越高越好
- **说明**：表示发现的bug数量。这是模糊测试的主要目标之一
- **目标**：发现尽可能多的安全漏洞和bug

#### 3. **路径数 (paths_total)**
- **含义**：发现的唯一执行路径数
- **期望**：越高越好
- **说明**：表示发现了多少种不同的程序行为。更多路径意味着测试更全面
- **目标**：探索更多的程序执行路径

#### 4. **偏好路径 (paths_favored)**
- **含义**：被标记为"偏好"的路径数
- **期望**：越高越好
- **说明**：表示有更多高质量的测试用例。这些路径通常覆盖了新的代码区域
- **目标**：产生更多有价值的测试用例

#### 5. **导入路径 (paths_imported)**
- **含义**：从其他模糊测试实例导入的路径数（在并行模糊测试中）
- **期望**：越高越好
- **说明**：表示与其他模糊测试实例的协作效果
- **目标**：在并行测试中更好地共享发现

---

### ⚖️ **需要平衡的指标**（效率 vs 效果）

#### 6. **执行次数 (execs_done)**
- **含义**：在测试时间内执行的测试用例总数
- **期望**：**在相同覆盖率下，越高越好**（表示效率高）
- **说明**：
  - **如果覆盖率相同**：执行次数越高，说明模糊测试速度越快，效率越高
  - **如果覆盖率不同**：需要看"覆盖率/执行次数"的比值（效率比）
  - **关键**：不是绝对数量，而是**效率**（单位时间内的覆盖率）
- **目标**：在保持高覆盖率的前提下，最大化执行速度

#### 7. **循环数 (cycles_done)**
- **含义**：完成的模糊测试循环数
- **期望**：**在相同覆盖率下，越低越好**（表示效率高）
- **说明**：
  - **如果覆盖率相同**：循环数越低，说明每个循环的效率越高，更快达到目标
  - **如果覆盖率不同**：需要综合考虑
  - **关键**：更少的循环达到相同的覆盖率 = 更高的效率
- **目标**：用更少的循环达到相同的覆盖率

---

## 效率指标（推荐使用）

### 1. **覆盖率效率** = 发现边数 / 执行次数
- **含义**：单位执行次数获得的覆盖率
- **期望**：越高越好
- **示例**：
  - 原策略：17 / 85049 = 0.0002
  - Lattice-MAB：17 / 91150 = 0.000187
  - **结论**：原策略效率更高

### 2. **循环效率** = 发现边数 / 循环数
- **含义**：每个循环获得的覆盖率
- **期望**：越高越好
- **示例**：
  - 原策略：17 / 73 = 0.233
  - Lattice-MAB：17 / 71 = 0.239
  - **结论**：Lattice-MAB 循环效率略高

### 3. **综合效率** = (发现边数 + 路径数) / 执行次数
- **含义**：单位执行次数获得的总体发现
- **期望**：越高越好

## 优化目标

### 理想情况

1. **覆盖率**：保持或提高（≥ 17）
2. **执行次数**：减少（< 85049）
3. **循环数**：减少（< 73）
4. **效率比**：提高（覆盖率/执行次数 > 0.000200）

### 优化后的预期

| 指标 | 目标 | 说明 |
|------|------|------|
| 发现边数 | ≥ 17 | 保持或提高覆盖率 |
| 执行次数 | < 85049 | 减少资源消耗 |
| 循环数 | < 73 | 提高循环效率 |
| 覆盖率效率 | > 0.000200 | 提高整体效率 |

## 总结

### ✅ 越高越好的指标
- 发现边数 (edges_found)
- 崩溃数 (unique_crashes)
- 路径数 (paths_total)
- 偏好路径 (paths_favored)
- 导入路径 (paths_imported)

### ⚖️ 需要平衡的指标
- **执行次数 (execs_done)**：在相同覆盖率下，越高越好（表示速度快）
- **循环数 (cycles_done)**：在相同覆盖率下，越低越好（表示效率高）

### 🎯 关键指标
- **覆盖率效率** = 发现边数 / 执行次数（最重要）
- **循环效率** = 发现边数 / 循环数

### 📊 优化方向
1. 保持或提高覆盖率
2. 减少执行次数（提高速度）
3. 减少循环数（提高效率）
4. 提高覆盖率效率（最终目标）
