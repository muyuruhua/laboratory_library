# Lattice-MAB 策略深度优化说明（V2）

## 优化目标

根据指标要求，本次优化旨在：
1. **减少执行次数**（< 85049）
2. **减少循环数**（< 73）
3. **提高覆盖率效率**（> 0.000200）
4. **保持覆盖率**（≥ 17）

## 主要优化措施

### 1. 进一步降低探索参数

| 参数 | V1 值 | V2 值 | 变化 |
|------|-------|-------|------|
| `MAB_ALPHA` | 0.03 | **0.01** | -67% |
| `MAB_EPSILON` | 0.05 | **0.02** | -60% |
| `NEIGHBOR_EXPLORE_PROB` | 10% | **5%** | -50% |

**效果**：大幅减少不必要的探索，更多时间用于利用已知高效策略。

### 2. 强化效率奖励机制

#### 2.1 效率奖励权重提升
```c
// V1: reward += efficiency * 5.0;
// V2: reward += efficiency * 20.0;  // 增加 4 倍
```

**效果**：效率成为奖励计算的主要因素，而非次要因素。

#### 2.2 更激进的效率惩罚
```c
// V1: EFFICIENCY_THRESHOLD = 100, EFFICIENCY_PENALTY_FACTOR = 0.1
// V2: EFFICIENCY_THRESHOLD = 50, EFFICIENCY_PENALTY_FACTOR = 0.3
```

**效果**：
- 更早触发惩罚（50次 vs 100次）
- 更强的惩罚力度（0.3 vs 0.1，增加 3 倍）

#### 2.3 渐进式惩罚机制
```c
// 根据效率等级进行渐进式惩罚
if (efficiency < MIN_EFFICIENCY_RATIO) {
    efficiency_factor = 0.4;  // 减少 60% UCB
} else if (efficiency < MIN_EFFICIENCY_RATIO * 2) {
    efficiency_factor = 0.6;  // 减少 40% UCB
} else if (efficiency < MIN_EFFICIENCY_RATIO * 5) {
    efficiency_factor = 0.8;  // 减少 20% UCB
}
```

**效果**：根据效率等级进行不同程度的惩罚，更精确地控制策略选择。

### 3. 优化 UCB 选择机制

#### 3.1 未探索策略的 UCB 值降低
```c
// V1: mab->arms[i].ucb_value = 1e10;  // 极高值，总是优先选择
// V2: mab->arms[i].ucb_value = 1.0;   // 适中值，更偏向已探索策略
```

**效果**：减少对新策略的盲目探索，更偏向利用已知高效策略。

#### 3.2 效率加权的 UCB 计算
```c
// 在选择时直接应用效率因子
mab->arms[i].ucb_value = (avg_reward + exploration) * efficiency_factor;
```

**效果**：低效策略的 UCB 值被显著降低，减少被选中的概率。

### 4. 智能邻居探索

#### 4.1 条件化邻居探索
```c
// 只在基础策略效率低时才探索邻居
if (base_efficiency < MIN_EFFICIENCY_RATIO * 2) {
    should_explore_neighbors = true;
}
```

**效果**：避免在高效策略上浪费计算资源探索邻居。

#### 4.2 双重条件邻居选择
```c
// 邻居必须同时满足：奖励更高 AND 效率更高
if (neighbor_reward > best_reward * 1.2 && 
    neighbor_efficiency > base_efficiency * 1.1) {
    // 考虑选择
}
```

**效果**：确保选择的邻居不仅在奖励上更好，在效率上也更好。

#### 4.3 提高邻居选择阈值
```c
// V1: neighbor_reward > best_reward * 1.1  (10% 更好)
// V2: neighbor_reward > best_reward * 1.2  (20% 更好)
//     且 neighbor_efficiency > base_efficiency * 1.1  (效率也要更好)
```

**效果**：更保守的邻居选择，避免频繁切换策略。

### 5. 奖励函数重构

#### 5.1 降低覆盖率权重
```c
// V1: reward = new_edges * 10.0 + new_paths * 5.0;
// V2: reward = new_edges * 5.0 + new_paths * 2.5;  // 减半
```

**效果**：降低覆盖率在奖励中的权重，更强调效率。

#### 5.2 效率成为主要因素
- 效率奖励权重：从 5.0 提升到 20.0（4倍）
- 效率惩罚力度：从 0.1 提升到 0.3（3倍）
- 效率阈值：从 100 降低到 50（更早触发）

**效果**：效率成为奖励计算的主导因素。

## 预期效果

### 执行次数
- **目标**：< 85049（减少至少 5%）
- **机制**：通过减少探索、惩罚低效策略、提高选择阈值

### 循环数
- **目标**：< 73（减少至少 5%）
- **机制**：通过更高效的策略选择，更快达到目标覆盖率

### 覆盖率效率
- **目标**：> 0.000200（提高至少 5%）
- **机制**：通过效率奖励和惩罚，优先选择高效策略

### 覆盖率
- **目标**：≥ 17（保持或提高）
- **机制**：在保持效率的同时，通过智能探索发现新路径

## 关键改进点总结

1. **探索减少 60-70%**：大幅降低探索参数
2. **效率权重提升 4 倍**：效率成为主要考虑因素
3. **惩罚提前且加强**：更早、更强地惩罚低效策略
4. **智能邻居探索**：只在必要时探索，且要求双重条件
5. **UCB 效率加权**：在选择时直接考虑效率
