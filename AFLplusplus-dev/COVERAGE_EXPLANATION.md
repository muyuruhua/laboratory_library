# AFL++ 覆盖率计算说明

## 覆盖率的基本概念

AFL++ 使用**边覆盖率（Edge Coverage）**来衡量代码覆盖率，这是基于**控制流图（Control Flow Graph, CFG）**的覆盖率度量。

## 边（Edge）的定义

### 什么是边？

在程序的控制流图中：
- **基本块（Basic Block）**：一段顺序执行的代码，只有一个入口和一个出口
- **边（Edge）**：从一个基本块到另一个基本块的跳转

例如：
```c
if (x > 0) {        // 基本块 A
    printf("pos");  // 基本块 B
} else {            // 基本块 C
    printf("neg");  // 基本块 D
}
```

这个代码有：
- 4 个基本块：A, B, C, D
- 3 条边：A→B, A→C, B→结束, C→结束

### 边的标识

AFL++ 使用以下公式为每条边分配唯一 ID：

```
edge_id = (previous_block_id ^ current_block_id) % map_size
```

其中：
- `previous_block_id`：前一个基本块的 ID
- `current_block_id`：当前基本块的 ID
- `map_size`：位图大小（通常是 65536 或更大）

## 位图（Bitmap）机制

### 位图结构

AFL++ 使用一个**共享内存位图**来跟踪边的执行情况：

```c
u8 trace_bits[MAP_SIZE];  // 位图数组
```

- 每个字节对应一条边（edge）
- 字节的值表示该边被执行的次数（经过分类处理）

### 执行次数分类

为了减少存储空间和提高效率，AFL++ 将执行次数分类到不同的"桶"中：

```c
static const u8 count_class_lookup8[256] = {
    [0] = 0,        // 未执行
    [1] = 1,        // 执行 1 次
    [2] = 2,        // 执行 2 次
    [3] = 4,        // 执行 3-4 次 → 归类为 4
    [4 ... 7] = 8,  // 执行 4-7 次 → 归类为 8
    [8 ... 15] = 16,    // 执行 8-15 次 → 归类为 16
    [16 ... 31] = 32,   // 执行 16-31 次 → 归类为 32
    [32 ... 127] = 64,  // 执行 32-127 次 → 归类为 64
    [128 ... 255] = 128 // 执行 128+ 次 → 归类为 128
};
```

**原因**：执行 23 次和执行 24 次通常没有太大区别，但执行 0 次和执行 1 次（或执行 1 次和执行 2 次）的区别很重要。

## edges_found 的计算

### 计算方法

`edges_found` 表示**发现的唯一边的数量**，通过以下方式计算：

```c
// 在 afl-fuzz-stats.c 中
t_bytes = count_non_255_bytes(afl, afl->virgin_bits);
edges_found = t_bytes;
```

### count_non_255_bytes 函数

```c
u32 count_non_255_bytes(afl_state_t *afl, u8 *mem) {
    u32 *ptr = (u32 *)mem;
    u32  i = ((afl->fsrv.real_map_size + 3) >> 2);
    u32  ret = 0;
    
    while (i--) {
        u32 v = *(ptr++);
        
        // 跳过全 0xff 的字节（未覆盖的边）
        if (likely(v == 0xffffffffU)) { continue; }
        
        // 检查每个字节是否非 255（即已被覆盖）
        if (v & 0x000000ffU) { ++ret; }  // 字节 0
        if (v & 0x0000ff00U) { ++ret; }  // 字节 1
        if (v & 0x00ff0000U) { ++ret; }  // 字节 2
        if (v & 0xff000000U) { ++ret; }  // 字节 3
    }
    
    return ret;
}
```

### virgin_bits 的含义

- **virgin_bits**：一个位图，记录哪些边**从未被覆盖**
- 初始值：所有字节都是 `0xff`（255）
- 当一条边被覆盖时：对应的字节被设置为非 255 的值
- **edges_found** = 位图中非 255 的字节数量 = 被覆盖的边的数量

## 覆盖率计算示例

### 示例 1：简单程序

假设一个程序有 100 条可能的边：
- 初始状态：`virgin_bits` 中所有 100 个字节都是 `0xff`
- `edges_found = 0`

执行测试用例后：
- 覆盖了 17 条边
- `virgin_bits` 中 17 个字节变为非 255
- `edges_found = 17`

### 示例 2：你的测试结果

```
原策略: edges=17
Lattice-MAB: edges=17
```

这表示：
- 两种策略都发现了 **17 条不同的边**
- 这 17 条边是 `test-whiteBox.c` 程序中所有可覆盖的边
- 覆盖率是 **100%**（17/17）

## 覆盖率 vs 执行次数

### 重要区别

- **edges_found（覆盖率）**：发现的**唯一边**的数量
  - 只关心"是否覆盖过"，不关心"覆盖了多少次"
  - 最大值：程序中所有可能的边数

- **execs_done（执行次数）**：执行的**测试用例总数**
  - 关心"执行了多少次"
  - 可以无限增长

### 覆盖率效率

```
覆盖率效率 = edges_found / execs_done
```

**含义**：单位执行次数获得的覆盖率

**示例**：
- 原策略：17 / 88832 = 0.000191
- Lattice-MAB：17 / 87093 = 0.000195
- **Lattice-MAB 效率更高**（用更少的执行次数达到相同的覆盖率）

## 覆盖率相关指标

### 1. edges_found（发现边数）
- **含义**：发现的唯一边的数量
- **计算**：`count_non_255_bytes(virgin_bits)`
- **范围**：0 到程序中所有可能的边数
- **越高越好**

### 2. paths_total（路径数）
- **含义**：发现的唯一执行路径数
- **计算**：基于边的组合和执行次数分类
- **说明**：不同的边组合形成不同的路径
- **越高越好**

### 3. paths_favored（偏好路径）
- **含义**：被标记为"偏好"的路径数
- **说明**：这些路径覆盖了新的代码区域
- **越高越好**

## 覆盖率在测试结果中的意义

### 你的测试结果

```
原策略: execs=88832, edges=17, cycles=73
Lattice-MAB: execs=87093, edges=17, cycles=72
```

**分析**：
1. **edges=17**：两种策略都发现了 17 条边
   - 说明 `test-whiteBox.c` 程序总共有 17 条可覆盖的边
   - 两种策略都达到了 **100% 覆盖率**

2. **execs 不同**：
   - 原策略：88832 次执行
   - Lattice-MAB：87093 次执行（**更少**）
   - **Lattice-MAB 用更少的执行次数达到了相同的覆盖率**

3. **覆盖率效率**：
   - 原策略：17 / 88832 = 0.000191
   - Lattice-MAB：17 / 87093 = 0.000195
   - **Lattice-MAB 效率高 2.09%**

## 总结

### 覆盖率计算流程

1. **插桩**：编译时在基本块之间插入代码，记录边的执行
2. **位图更新**：执行时更新共享内存位图
3. **分类处理**：将执行次数分类到不同的桶中
4. **统计计算**：统计 `virgin_bits` 中非 255 的字节数 = `edges_found`

### 关键要点

- **edges_found** = 发现的唯一边数 = 代码覆盖率
- **覆盖率效率** = edges_found / execs_done = 单位执行次数的覆盖率
- **你的结果**：Lattice-MAB 用更少的执行次数达到了相同的覆盖率（17 条边），效率更高

### 为什么 edges=17？

`test-whiteBox.c` 程序的结构决定了它有 17 条可覆盖的边：
- 多个 if-else 分支
- 函数调用（is_even）
- 各种条件组合

两种策略都达到了 100% 覆盖率，但 Lattice-MAB 用更少的资源达到了这个目标。
